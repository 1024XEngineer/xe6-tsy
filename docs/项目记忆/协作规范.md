# 协作规范

更新时间：2026-07-15

## 分支约束

- Codex 不得创建任何目标为 `main` 的 Pull Request。
- Codex 不得合并或直接推送 `main`。
- 当前基础框架只在现有 `dev` 分支实现、验证、提交和推送。
- 如需改变目标分支，必须由用户后续明确指定；不得从一般性“提交”推断为可操作 `main`。

## 工程交付

- 先有 Issue、Proposal/架构输入和验收标准，再提交代码。
- 架构骨架必须有真实接口、数据模型和模块调用，不能只有目录占位。
- 实现可以是 fake/stub，但必须可编译、可测试并可重复运行主链。
- 正式 PR 应关联工程 Issue，经过自动检查、AI 质量检查和人工 Review。
- Issue #37 当前仍是技术选型/架构输入，不由基础框架提交直接关闭。

## 验证

- 提交前运行格式检查、`go vet`、单测、race test 和 build；存在 contract 时同时运行 contract 校验。
- CI 不依赖真实供应商、云密钥、网络模型结果或真实个人数据。
- 不能把计划、个人 fork 或本地未提交文件当作组织仓库交付证据。
